## 들어가며

인턴십 기간 동안 오디오 툴킷의 프론트엔드를 맡았다. 오디오 툴킷은 영상을 업로드하면 장면에 맞는 효과음을 추천·생성해주는 **효과음 생성** 기능과, 음성을 인식해 자막을 만들고 편집·스타일링할 수 있는 **자막 생성** 기능으로 구성된 서비스다.

이 글은 매일 작성한 데일리 스크럼을 바탕으로 정리했다. 무엇을 만들었는지와 함께, 기능을 만들면서 어떤 설계 판단을 했고 어떤 문제를 어떻게 풀었는지를 중심으로 적었다.

## 효과음 생성 페이지

### 영상 업로드와 미리보기

영상을 드래그해 올릴 수 있는 업로드 영역을 만들고, 업로드된 영상의 정보 표시와 미리보기, 재생·정지 기능을 구현했다. 영상 정보 영역은 기능 명세서에 맞춰 수정했고, 생성·삭제 버튼과 모달의 포커스 트랩도 함께 다듬었다. 이후 MVP 개선 단계에서는 다른 파일을 드래그하면 기존 파일이 교체되도록 바꿨다.

### 파형 타임라인과 효과음 선택

오디오 파형 UI 위에 효과음이 생성될 위치를 마커로 표시하고, 한 구간에 추천 효과음이 여러 개일 경우 하단 영역에 모아 보여주도록 했다. 사용자는 이 중에서 적용할 효과음을 선택하고 미리 들어볼 수 있다.

타임라인 사용성을 위해 다음 보조 기능을 추가했다.

- **재생헤드 동기화** — 영상 재생 위치를 타임라인이 실시간으로 따라가고, 드래그로 직접 탐색할 수 있다.
- **자동 스크롤** — 마커 클릭, 다음 구간 이동, 재생 중 화면 밖으로 벗어날 때 타임라인이 따라 스크롤된다.
- **효과음 오버레이 미리듣기** — 원본 소리를 유지한 채 적용된 구간에서 효과음을 겹쳐 재생한다.

### 설계하면서 정한 원칙

효과음 선택·적용 흐름을 만들면서 다음 기준을 세웠다.

- **선택(로컬)과 적용(확정)을 분리했다.** 사용자가 여러 효과음을 들어보며 마음을 바꿔도 서버 요청 없이 바꿀 수 있게 하기 위해서다.
- **추천이 1개뿐인 구간은 자동으로 적용했다.** 고민할 필요가 없는 구간까지 하나하나 확인시키지 않기 위해서다.
- **삭제는 마커를 없애지 않고 색만 바꿨다.** 실수로 삭제해도 복구할 수 있고, 전체 처리 현황을 색으로 한눈에 파악할 수 있다.
- **일괄 적용 옵션을 제공했다.** 중복 추천이 최대 3개로 많지 않다는 점을 고려해, 하나씩 확인하거나 일괄 처리하는 방식 중 사용자가 고를 수 있게 했다.
- **미리보기와 최종본의 경로를 나눴다.** 브라우저 미리보기는 원본 위에 효과음을 겹쳐 재생하는 방식이고, 실제 파일 합성은 최종 적용 이후 백엔드에서 처리된다.

### 최종 적용과 다운로드

적용할 데이터를 서버로 보내는 동안 로딩 스피너를, 완료되면 Toast 메시지를 보여주도록 했다. 최종 적용이 끝나면 편집 구간을 조작할 수 없게 비활성화하고 다운로드 버튼을 제공했다. 이 과정에서 "다시 선택하기" 버튼은 카드 선택 토글로 대체해 없앴고, 효과음 제거 시에는 최종 적용에 포함되지 않는 구간이 된다는 안내 모달을 띄우도록 했다.

### 효과음 재생성

추천된 효과음이 마음에 들지 않을 때를 위해 재생성 기능을 추가했다. 재생성 버튼을 누르면 프롬프트 입력창이 나타나고, 사용자가 원하는 소리를 텍스트로 설명하면(예: "쨍그랑 유리 깨지는 소리") 서버로 전송된다. 요청 중에는 버튼이 로딩 상태로 바뀌고, 응답이 오면 새 효과음이 기존 추천 목록에 카드로 추가된다. 기존 카드는 그대로 유지되며, 새 카드를 선택하면 해당 구간으로 이동해 자동 재생된다.

## 자막 생성 페이지

### 업로드와 타임라인 동기화

영상 업로드 성공·실패 처리, 미리보기, 업로드된 영상 정보 표시, 삭제 안내 모달과 삭제 기능을 구현했다. 추출된 자막을 타임라인에 표시하고, 타임라인 자막과 영상 재생을 동기화해 미리보기 영역에 해당 구간의 자막이 나타나도록 했다. 자막 생성 이후에는 파일을 삭제하기 전까지 추가 업로드를 막았다.

### 자막 편집

타임라인의 자막을 클릭하면 편집 영역에 해당 자막 정보가 표시되고, 편집 모드를 켜야 내용을 수정할 수 있다. 편집한 내용을 적용하지 않고 다른 작업을 클릭하면 안내 모달을 띄웠다.

처음에는 편집 영역의 버튼을 "자막 적용"이라고 불렀는데, 최종 적용과 헷갈릴 수 있어 **"임시저장"으로 문구를 바꿨다.** 편집 내용은 먼저 로컬에 임시저장되고, 최종 적용 버튼을 눌러야 서버에 저장되는 흐름을 사용자가 문구만으로 이해할 수 있게 하기 위해서다. 이후 편집 모드도 리팩토링해, 임시저장 후나 편집 없이 다른 구간으로 이동할 때는 편집 모드가 자동으로 꺼지도록 했다.

### ASS 자막 스타일링

ASS 형식은 스타일 속성이 많아서, 사용자가 조절할 수 있는 항목을 일부로 추렸다. 접근성을 고려해 마크업했고, 자막 편집 중 스타일링으로 넘어가거나 스타일링 도중 타임라인·자막 편집을 클릭할 때 작업이 유실되지 않도록 방어 장치를 두었다. ASS 파일로 다운로드했을 때 스타일이 실제로 반영되는 것도 확인했다.

스타일링과 다운로드의 관계는 한 번 바뀌었다. 처음에는 스타일을 적용하지 않아도 다운로드할 수 있게 했지만, 이후 **스타일을 수정해놓고 적용하지 않은 상태에서는 다운로드 버튼을 비활성화하도록** 흐름을 수정했다. 수정한 스타일이 반영되지 않은 파일을 받는 상황을 막기 위해서다. 기본값을 불러오는 초기화 버튼도 추가했는데, 초기화만으로는 적용되지 않기 때문에 스타일 적용을 눌러달라는 Toast 메시지를 함께 보여주도록 했다.

최종 적용 이후에는 자막 편집과 스타일링을 비활성화하고, 타임라인 탐색과 영상 재생만 가능하도록 했다.

## 서버 연동 후 버그 수정

로컬에서 완성한 기능을 실제 API와 서버 환경에 연결하면서 여러 버그가 드러났다.

### 최종 적용 버튼 무한 로딩

**문제** — 효과음 최종 적용 버튼을 누르면 로딩 상태에서 벗어나지 못했다.
**원인** — 최종 적용 진행 상태를 효과음 관련 훅이 감지하지 못하는 구조였다.
**해결** — `useAudioTracks`의 `refetchInterval` 구조를 수정해, 최종 적용 상태도 훅에서 감지할 수 있도록 했다.

### 효과음 구간 삭제 버그

**문제** — 영상의 특정 구간에서 효과음 삭제가 의도대로 동작하지 않았다.
**해결** — 적용 여부를 판단하는 조건에 "로컬에서 선택된 효과음이 있는지"를 추가했다. 선택(로컬)과 적용(확정)을 분리한 설계에서, 두 상태를 모두 고려하지 않은 조건이 있었던 것이다.

### 서버 환경 테스트 중 발견된 문제

- 서버 주소를 절대경로로 받아오도록 수정했다.
- 영상 업로드 후 효과음 생성이 완료되어야만 미리보기·편집 영역이 보이도록 수정했다.
- 최종 적용이 실패하면 사용자가 확인할 수 있는 문구와 다시 시도 버튼을 제공했다.
- 업로드 성공 Toast 메시지와 효과음 생성 전 영상 미리보기가 로컬과 서버 환경의 차이로 타이밍이 어긋나, 업로드 성공 Toast를 제거했다.

### 효과음 재생 로직 개선

영상 재생과 효과음 재생이 서로 얽히면서 다음 문제들이 있었고, 재생 로직을 개선해 해결했다.

- 한 구간의 효과음을 재생한 뒤 그 구간으로 다시 돌아가면 소리가 나지 않았다.
- 영상을 일시정지해도 효과음이 계속 재생됐다.
- 영상이 끝까지 재생된 뒤 같은 구간의 마커를 다시 클릭하면 소리가 나지 않았다.

이어서 재생 간의 관계도 정리했다. 효과음 카드를 선택하면 해당 구간으로 영상이 이동하고, 효과음 재생 버튼을 누르면 영상이 멈추며, 효과음 재생 중 마커를 클릭하면 효과음이 멈추도록 했다. 효과음 듣기의 중복 재생도 막았다.

### 자막 생성 페이지 상태 관리

- 이전에 업로드한 영상 이력 상태가 남아 있어, 새 영상을 올려도 최종 적용 버튼이 나타나는 문제가 있었다. 업로드 시 이전 상태를 리셋하도록 수정했다.
- 스타일 초기화 후 저장하지 않고 이동하려 할 때 뜨는 안내 모달에서 "저장하고 이동"을 눌러도 적용이 반영되지 않는 버그를 수정했다.
- 기본 스타일 상태에서 초기화 버튼을 누를 때 나오는 안내 모달의 버튼 오작동을 수정했다.
- 최종 적용 버튼의 동작 방식을 알려주는 안내 모달을 추가했다.

## 백엔드와 협업하며 제안한 것

- **진행률 표시** — 프로그레스 바를 만들려면 백엔드에서 처리 진행률을 보내줘야 하기 때문에, 우선 로딩 스피너로 불러오는 중임을 알리기로 했다.
- **한글 파일명 깨짐 방지** — 영상 업로드 시 파일 자체의 이름 정보와 별도로 `originalFileName: file.name`을 텍스트 값으로 함께 보내는 방식을 제안했다. 서버는 저장용 파일명을 자유롭게 정하고, 화면에 보여줄 원래 파일명은 이 값을 저장해뒀다가 그대로 돌려주면 된다.
- **MVP 개선사항 코멘트** — 개선사항을 반영하면서 판단이 필요한 부분에는 코멘트를 남겨 공유했다.

## 돌아보며

**상태의 경계를 명확히 하는 것이 대부분의 문제를 좌우했다.** 효과음 선택(로컬)과 적용(확정), 자막 임시저장과 최종 적용, 스타일 수정과 적용처럼, 이 프로젝트의 핵심 흐름은 대부분 "아직 확정되지 않은 상태"와 "확정된 상태"를 구분하는 일이었다. 설계 단계에서 이 경계를 나눈 덕분에 사용자가 자유롭게 시도해볼 수 있는 흐름을 만들 수 있었지만, 버그의 상당수도 이 경계에서 나왔다. 구간 삭제 버그처럼 한쪽 상태만 보고 판단한 조건이 있었고, 최종 적용 무한 로딩처럼 서버 쪽 상태 변화를 화면이 따라가지 못하는 경우도 있었다.

**로컬에서 동작하는 것과 서버에서 동작하는 것은 달랐다.** 효과음 생성 페이지의 기능을 07.13에 전반적으로 완성했지만, 실제 데이터와 서버 환경에 연결하고 나서야 서버 주소, 생성 완료 전 화면 노출, 타이밍 차이 같은 문제가 드러났다. 기능 완성과 서비스 완성 사이에는 연동과 검증이라는 단계가 따로 있다는 것을 체감했다.

**사용자 흐름은 한 번에 정해지지 않았다.** 다운로드 버튼 활성화 조건, "자막 적용"에서 "임시저장"으로의 문구 변경, 최종 적용 이후 무엇을 막고 무엇을 허용할지는 모두 구현하고 사용해보면서 다시 조정한 결과다. 모달과 방어 장치를 추가할 때마다 "사용자가 이 상황에서 작업을 잃지 않는가, 지금 무슨 일이 일어나는지 아는가"를 기준으로 삼게 되었다.
