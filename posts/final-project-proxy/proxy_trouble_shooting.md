로그인 여부와 사용자 역할에 따라 접근 가능한 페이지 영역을 제한하기 위해, Next.js에서 제공하는 프록시를 사용하여 페이지가 렌더링되기 전에 사용자의 역할을 검사하는 로직을 구성하였다. 로그인하기 전에 사용자가 마이페이지 url로 접근 시에 로그인 모달창이 나와 로그인을 유도하는 로직까지는 브라우저에서 잘 적용이 되었다.

## 문제 상황

![](https://velog.velcdn.com/images/ruiwaa/post/b9ac1f25-8ea1-4b5f-b661-337f3e289e78/image.png)

### 1) 문제 발생

사용자의 역할을 소비자와 판매자 이렇게 두 가지의 역할로 나눠지는데, 해당 사용자의 역할을 user_metaData에서 role을 읽어오게하여, 사용자의 역할에 따라 렌더링된 마이페이지만 접근 할 수 있도록 로직을 작성했는데, 서로의 역할이 아닌 다른 마이페이지로도 접근이 가능한 문제가 발생하였다.

### 2) 디버깅

해당 사용자의 역할을 user_metaData에서 role을 콘솔값에 직접 넣어, 제대로 불러와지는지를 확인하였다. 그 결과 콘솔값에 undefined라는 값이 출력되어, 데이터가 제대로 읽어와지지 않는 문제를 확인하였다. supabase에 role를 metadata에 저장하는 형식이 아니었기때문에 역할에 따라 렌더링된 마이페이지외에도 다른 역할의 마이페이지에도 접근이 가능한 것이었다.

## 해결과정

![](https://velog.velcdn.com/images/ruiwaa/post/581b5729-877e-4625-adca-e2f03d5038b9/image.png)

supabase.from('users').select('role') 직접적으로 연결해서 DB 테이블에서 조회하여 역할을 불러옴.

사용자의 역할이 아닌 마이페이지 경로를 입력하여 접근하려고 할 시, 해당 역할에 맞는 마이페이지로 리디렉션을 시키는 구조로 수정 완료.
