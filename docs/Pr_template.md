## ⚠️ 결과(트러블슈팅) 작성 원칙 (RESULT_WRITING_RULE)

Claude Code가 트러블슈팅의 "결과"를 쓸 때 반드시 지켜야 하는 규칙:

1. **실제로 테스트/확인한 사실만 쓴다.** 코드를 고쳤다는 이유만으로 효과를 추정해서 쓰지 않는다.
2. **수치는 실측값만 허용한다.** 예: 실제로 Lighthouse를 돌려서 나온 점수, 실제로 콘솔에서 확인한 에러 개수, 실제로 측정한 로딩 시간. 실측하지 않았다면 절대 숫자를 만들어 쓰지 않는다.
3. **측정하지 않았다면 정성적으로 서술한다.** "~가 정상적으로 동작함을 확인", "재현되던 에러가 더 이상 발생하지 않음" 같은 사실 기반 문장으로 대체한다.
4. **해결이 서비스/사용자에게 주는 실질적 이점을 한 줄 덧붙인다.** 단, 이 역시 과장이나 추측이 아니라 해결한 문제와 직접 연결되는 내용이어야 한다. (예: "다크 모드 전환 시 상태가 꼬이지 않아 사용자가 테마를 바꿔도 이전 값이 남아있는 버그 없이 사용 가능")
5. **모르면 모른다고 쓴다.** "정확한 성능 개선폭은 별도 측정이 필요함" 처럼 한계를 명시하는 것이 허위 수치보다 낫다.
